# mut · desktop interface

Svelte 5 + TypeScript + Vite. Реализация desktop-макетов из Paper `mut`:
https://app.paper.design/file/01M3PX4ZS5H909QX385GZP43FJ/p-1-0

## Просмотр дизайна

```sh
cd frontend
npm ci
npm run dev
```

Откройте адрес, который выводит Vite. Без Wails автоматически включается
режим дизайна: 12 демонстрационных книг из референса и переключатель экранов
внизу. Этот режим не вызывает Go и не изменяет настоящий архив.

Можно открыть конкретный экран через `?preview=…`:

| Значение                        | Экран                                   |
| ------------------------------- | --------------------------------------- |
| `library`, `empty`              | Библиотека с книгами / пустое состояние |
| `login`, `create`, `recovery`   | Вход / создание / сохранение кода       |
| `reader`, `pdf`, `fb2`          | Оболочка чтения EPUB / PDF / FB2        |
| `unsupported`                   | Карточка формата без встроенного чтения |
| `settings`                      | Настройки                               |
| `import`, `duplicate`, `issues` | Импорт / дубликат / отчёт об ошибках    |
| `backup`, `verify`, `verified`  | Создание / проверка / результат копии   |
| `restore`, `restored`           | Восстановление / результат              |

Экраны копирования и проверки в этом режиме демонстрационные. Реальных
операций с файлами нет. Закладки и позиции в демонстрационной читалке
живут только в памяти. Для PDF сейчас показан макет страницы, а не PDF.js.

## Что подключено

При наличии Wails и без `?preview` используются существующие bindings:
`IsVaultConfigurated`, `IsUnlocked`, `CreateVault(path, password)`,
`Unlock(path, password)`, `UnlockWithRecovery(path, code)`, `ListBooks`,
`ListShelves`, `ImportBook(path)`, `Lock`.

Поля путей заполнены стандартными значениями, имеют кнопку «По умолчанию»
и запоминают выбранные директории между запусками. «Обзор…» и
«Выбрать файлы…» подключаются автоматически при наличии соответствующих
методов моста; пока их нет, пути вводятся вручную. Контракт для реализации
на стороне Go описан в [BRIDGE.md](BRIDGE.md).
Импорт принимает любой формат и обрабатывает очередь последовательно.
Остановка прекращает очередь после текущего файла; закрытие диалога также
останавливает очередь. Создание полок, оригинальные обложки, экспорт,
резервные копии и реальные ридеры требуют следующих методов моста.
Их действия пока недоступны в обычном режиме; демонстрационный успех там
не показывается. В ядро хранения изменений не внесено.

`main.go` встраивает `frontend/dist` в приложение. Перед Go-сборкой нужен
`npm run build`; Wails выполняет его через `wails.json`.

## Интерфейс

- Тёмная и светлая темы, Onest для UI и Literata для страницы чтения.
- Фирменный логотип из `pictures/mut-logo-transparent.png`.
- Полки, поиск по названию/автору, фильтры статуса и сортировка.
- Сетка/список с виртуализацией строк, две плотности обложек.
- Отдельные пустые состояния коллекции, полки и поиска.
- Native `<dialog>`: захват/возврат фокуса, закрытие по Escape и фону.
- Видимый фокус, Ctrl/Cmd+K для поиска, стрелки в демонстрационной читалке.
- В `localStorage` сохраняются оформление и выбранные директории, без книг, паролей и кодов.
- Все шрифты и изображения локальные; сетевые ресурсы не используются.
- Шрифты лицензированы по SIL OFL 1.1; лицензия включена в сборку.

## Проверка

```sh
npm run check
npm run build
```

Svelte/TypeScript проверяются отдельно от сгенерированного Wails JavaScript;
типизированный контракт берётся из `App.d.ts` и `models.ts`.

Проверено в Chromium: 18 состояний; поиск, фильтры, сетка/список,
проверка последних 6 символов кода, модальные окна, тема, управление страницей,
блокировка. Размеры 1440×900, 1024×768 и 390×844. Проверка Chromium
не заменяет проверку desktop-сборки в WebKitGTK и замеры на большой коллекции.
