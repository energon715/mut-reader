# Архив mut, версия 1

Описание фактического формата этой ветки. Публичная заморозка формата ожидает
независимого ревью. Изменения шифрования требуют новой версии и явной миграции.

## Структура

```
vault.json
HEAD
objects/<первые два символа UUID>/<UUID>
snapshots/<UUID>
.mut-lock
```

UUID записываются в каноническом нижнем регистре. HEAD — UUID последнего снимка
и перевод строки. `.mut-lock` — служебная блокировка desktop, не часть копии.
Файлы создаются с правами 0600, новые директории — 0700. Права уже существующих
директорий автоматически не меняются.

`vault.json`: `version=1`, `vault_id`, `kdf` (`salt`, `time`, `memory`, `threads`),
`wrapped_master_key`, `key_nonce`, `mobile_recovery`. Байты JSON — стандартный
Base64 с padding. Историческое имя `mobile_recovery` сохраняется для совместимости
и содержит recovery-конверт desktop; совместимость с мобильным прототипом не заявлена.

## Криптографические конверты

Master key — 32 случайных байта. Argon2id выводит 32-байтовый ключ из UTF-8 пароля;
по умолчанию соль 32 байта, time=3, memory=65536 КиБ, threads=4.
Параметры проверяются перед KDF: соль 16–64 байта, time 1–10,
memory 8192–262144 КиБ, threads 1–16.

XChaCha20-Poly1305: nonce 24 байта, тег 16 байт. `wrapped_master_key` —
зашифрованный master key с AAD UTF-8 `vault_id`; `key_nonce` хранится отдельно.

Recovery-код — Base64 URL без padding от 32 случайных байтов (43 символа).
Эти байты служат ключом второго конверта master key. `mobile_recovery` —
`nonce || ciphertext || tag`, AAD `vault_id + ":recovery"`, всего 72 байта.
Смена пароля заменяет KDF и парольный конверт, сохраняя master key и recovery.

Ключ сущности: HKDF-SHA256(master key, salt=UTF-8 vault_id,
info=UTF-8 `mut:<kind>:<entity UUID>`, output=32 байта).
Для оригинала/обложки kind=`object`, для каталога kind=`snapshot`.
Файл сущности — `nonce || ciphertext || tag` без дополнительного заголовка.
AAD: `object:<UUID>` либо `snapshot:<UUID>` соответственно.
Это единый конверт целого файла; потоковое/блочное шифрование не реализовано.

Каталог — зашифрованный JSON Snapshot. Читаются version=0 (старые снимки)
и version=1. Новые снимки используют version=1. Поля книг описаны типом
`internal/catalog.Book`: оригинальный объект, SHA-256, размер, название, автор,
формат, обложка, полки, позиция и закладки. Позиции: `v1:pdf:<страница>`
или `v1:text:<глава с нуля>:<индекс блока с нуля>`. Исходные байты неизменны.

## Фиксация и копия

Сначала записываются и синхронизируются объекты, затем новый неизменяемый снимок,
затем временный HEAD с fsync → атомарная замена → fsync директории.
Незавершённые временные файлы и недостижимые сущности могут остаться после сбоя.
Если ошибка возникла после rename, результат фиксации может быть неопределённым;
повторно откройте архив перед следующей записью. Тест прекращения процесса
не заменяет проверку физического отключения питания.

Копия содержит разрешённые файлы архива и `manifest.json`:
version=1, createdat, snapshotid, vault_id, files (относительный путь → SHA-256).
В неё включаются старые снимки и недостижимые объекты. Манифест не подписан.
Копия и восстановление сначала создаются во временной соседней директории;
публикация через Linux renameat2(RENAME_NOREPLACE) не заменяет существующую цель.

## Лимиты и совместимость

Объект: 256 МиБ plaintext; snapshot: 64 МиБ; заголовок: 64 КиБ;
каталог: 100000 книг/10000 полок; манифест: 100000 файлов/64 МиБ.
Ограничение манифеста может достигаться раньше ограничения каталога.
Ограничения читалок не меняют формат архива: модель EPUB/FB2 — до 32 МиБ,
500000 токенов; EPUB spine — до 4096 записей.
Все оригиналы экспортируются без преобразований и проверяются по SHA-256.
Обложки сохраняются как зашифрованные data URI PNG/JPEG/GIF.

Неизвестные версии отклоняются. Миграция должна создавать новую папку,
проверять оригиналы и оставлять исходную. Автоматических миграций сейчас нет.
