# mut — план выпуска 1.0.0

Дата: 13 октября 2026 года. Область: Linux desktop, одна локальная библиотека,
один пользователь. Этот документ фиксирует задачи и критерии готовности;
он не означает, что перечисленные функции уже реализованы или проверены.

Основание: [PRODUCT.md](PRODUCT.md), [ARCHITECTURE.md](ARCHITECTURE.md),
[SECURITY.md](SECURITY.md) и [ROADMAP.md](ROADMAP.md). Требования безопасности
имеют приоритет. Go-ядро и мост реализует автор проекта.

## Что должна уметь версия 1.0.0

Полный пользовательский цикл:

**Создать архив → импортировать → читать → закрыть приложение → продолжить
чтение → сделать копию → восстановить на другом компьютере.**

Все этапы работают без аккаунта, сервера и подключения к интернету.
Импорт сохраняет файлы любого формата. Встроенное чтение первой версии
поддерживает PDF, EPUB и FB2. Для остальных форматов доступен экспорт оригинала.

## Состояние на момент составления

По просмотренному рабочему каталогу уже существуют пакеты зашифрованного
хранилища, каталога, импорта, резервирования и восстановления, а также CLI
`vaultctl`. Desktop-фронт содержит дизайн основных экранов и часть вызовов моста.

Оболочка чтения пока не отображает настоящие книги. Полки, экспорт, резервные
копии и восстановление ещё требуют подключения к интерфейсу. Наличие функции
в пакете или макета экрана не означает готовность пользовательского сценария.

Проверка интерфейса на 10 000 тестовых карточках не является нагрузочной
проверкой ядра, реального импорта или чтения больших книг.

- [ ] Получать стандартные пути для пользователя, запускающего приложение.
- [ ] Подключить системный выбор папки и нескольких файлов.
- [ ] Подключить операции управления полками, экспорт оригинала,
      создание и проверку копии, восстановление.
- [ ] Добавить методы открытия книги, передачи содержимого ридеру,
      сохранения позиции и управления закладками.
- [ ] Перегенерировать Wails bindings после изменения методов и типов.
- [ ] Возвращать понятные ошибки и состояние операций без секретов
      и содержимого книг в диагностических логах.
- [ ] Проверять доступ к библиотеке в Go для каждого действия.

Контракт системных диалогов, ожидаемый фронтом:

| Метод | Результат |
| --- | --- |
| `GetDefaultPaths()` | Абсолютные пути в полях `library`, `backup`, `restore`, `imports` |
| `ChooseDirectory(title, currentPath)` | Полный путь выбранной папки; пустая строка при отмене |
| `ChooseFiles(currentDirectory)` | Список полных путей; пустой список при отмене |

Для Wails v2 используются системные диалоги с контекстом приложения.
Начальная директория должна существовать: для нового пути архива нужно найти
ближайшего существующего родителя. Диалог выбора папки позволяет создать папку,
а диалог импорта принимает любые форматы.

**Критерий готовности:** действия выполняются из приложения; отмена диалога
сохраняет прежний путь. Выбранные пути восстанавливаются после перезапуска,
пароль и recovery-код не сохраняются. Возврат из копий или восстановления
сохраняет исходный экран и открытую сессию, включая пустую библиотеку.

## 2. Интегрировать настоящие читалки

- [ ] PDF: отображение страниц, переход к странице, масштабирование.
- [ ] EPUB: отображение текста, оглавление, переходы, размер текста.
- [ ] FB2: безопасный разбор и отображение текста, оглавление, размер текста.
- [ ] Сохранять позицию чтения и прогресс в зашифрованном каталоге.
- [ ] Добавлять, удалять и открывать несколько закладок.
- [ ] Продолжать чтение с сохранённой позиции после закрытия приложения.
- [ ] Использовать версионированные указатели позиции для каждого формата.
- [ ] Закрывать ридер и прекращать выдачу содержимого при блокировке.
- [ ] Поставлять движки, шрифты и остальные ресурсы локально.

Планируемые решения из архитектуры: PDF.js, epub.js как кандидат для EPUB,
ограниченная внутренняя модель документа для FB2. Разбор метаданных при импорте
не заменяет реализацию чтения.

**Критерий готовности:** настоящая книга каждого из трёх форматов читается
в desktop-приложении; навигация, закладки и продолжение работают после
перезапуска. Проверка проводится в WebKitGTK, а не только в Chromium.

Исходные файлы при импорте не удаляются.

## 4. Закончить проверяемое резервирование

- [ ] Снимать согласованное состояние каталога и достижимых объектов.
- [ ] Исключить смешивание состояний при одновременном импорте или изменении
      каталога; определить порядок и синхронизацию операций.
- [ ] Не создавать копию внутри исходного сейфа и не затирать сейф копией.
- [ ] После записи перечитать копию и сверить контрольные суммы.
- [ ] Проверять обязательные файлы, версию и структуру манифеста.
- [ ] При восстановлении проверить доступ паролем или полным recovery-кодом,
      каталог и расшифрование объектов, включая целостность AEAD.
- [ ] Восстанавливать в новую пустую папку, сохраняя исходную библиотеку и копию.
- [ ] Не представлять частично записанную папку как завершённое восстановление.
- [ ] Показывать реальный результат проверки, включая ошибки.
- [ ] Проверить восстановление через `vaultctl` без desktop-приложения.

SHA-256 манифеста проверяет совпадение файлов с записанными хешами.
Это само по себе не доказывает, что копию можно расшифровать и восстановить.

**Критерий готовности:** копия восстановлена на чистой машине без сети;
каталог, полки, позиции и закладки доступны, а все экспортированные оригиналы
совпадают с исходными по хешам.

## 5. Закрыть вопросы сохранности и безопасности

### Конкретные пункты из просмотренного кода

- [ ] В `internal/backup/backup.go` проверять пути из манифеста до чтения
      и записи. Не допускать выхода за пределы папок через `..` или символьные
      ссылки. Проверять как источник копии, так и цель восстановления.
- [ ] В `internal/vault/snapshots.go` обеспечить корректный порядок записи
      объектов, snapshot и `HEAD`, включая синхронизацию файлов и директорий
      с диском. Одной замены `HEAD` через `Rename` недостаточно для подтверждения
      сохранности при аварии питания.
- [ ] Проверить сохранность при создании сейфа, смене пароля и записи объектов,
      включая ошибки записи, закрытия файлов и заполнение диска.

Это выявленные задачи для проверки и исправления, а не полный security-аудит.

### Остальные обязательные проверки

- [ ] Валидировать версию заголовка, размеры nonce и ключевых полей,
      допустимые параметры KDF до криптографических операций.
- [ ] Установить ограничения памяти, размеров файлов, распаковки EPUB,
      числа записей и сложности разбора XML.
- [ ] Не исполнять скрипты книг и не загружать внешние ресурсы автоматически.
- [ ] Проверить изоляцию активного EPUB-контента в целевом WebKitGTK.
- [ ] Проверить блокировку во время чтения и фоновых операций, включая
      отсутствие возврата метаданных из запоздавшего ответа моста.
- [ ] Добавить блокировку по таймеру и определить поведение при закрытии окна.
- [ ] Не сохранять открытые книги, обложки, пароли или recovery-коды
      в постоянные кеши, логи или настройки.
- [ ] Подготовить тестовые векторы формата и fuzzing декодеров и импортёров.
- [ ] Перед публичным релизом с заявленной защитой данных провести независимое
      ревью криптографического формата и обработки недоверенных книг,
      как требуют `SECURITY.md` и `ROADMAP.md`.

**Критерий готовности:** после сбоя доступно старое или новое согласованное
состояние; известные критические ошибки утечки и потери данных закрыты.
Границы защиты документированы без обещаний абсолютной безопасности.

## 6. Проверить полный цикл на реальных данных

- [ ] Обычные, повреждённые и многоязычные PDF, EPUB и FB2.
- [ ] Файлы форматов без адаптера чтения: импорт, копия, восстановление, экспорт.
- [ ] Неправильный пароль, полный recovery-код, смена пароля и повторное открытие.
- [ ] Recovery при создании: подтверждение последних 6 символов;
      recovery при входе: проверка полного кода ядром.
- [ ] Дубликаты, одинаковые имена файлов и отмена импорта.
- [ ] Заполненный диск, недоступная папка, ошибки чтения и записи.
- [ ] Принудительное завершение процесса на этапах импорта и фиксации каталога.
- [ ] Копия повреждена, неполна или содержит некорректный манифест.
- [ ] Восстановление на чистой машине и сравнение каждого оригинала по хешу.
- [ ] Реальные коллекции из 1, 100, 1 000 и 10 000 книг, большие книги,
      слабый ноутбук и HiDPI.
- [ ] Измерить время и память запуска, разблокировки, импорта и чтения;
      зафиксировать бюджеты после измерений.
- [ ] Проверить работу без сети и отсутствие нежелательных исходящих запросов.
- [ ] Дать нескольким друзьям пройти импорт, чтение и восстановление без подсказок;
      исправить выявленные проблемы.

**Критерий готовности:** результаты воспроизводимы; приложение не зависает
на типичной коллекции, а ошибки не приводят к молчаливой потере данных.

## Ближайший практический этап

1. Подключить стандартные пути и системные диалоги.
2. Интегрировать одну настоящую читалку, включая сохранение позиции.
3. Подключить копирование, проверку, восстановление и экспорт.
4. Пройти полный цикл с одной книгой каждого из трёх форматов.
5. Довести оставшиеся функции и проверки из этого списка до релиза.

Этот этап даёт работающий прототип полного цикла. Он не заменяет проверки
сохранности и безопасности, необходимые для публичной 1.0.0.

## Что оставить после 1.0.0

AI, обмен книгами и капсулы, синхронизация, облачные копии, дополнительные
адаптеры чтения, OCR, социальные функции, Windows/macOS и мобильный клиент
не входят в обязательную область этого desktop-релиза.

## Решение о выпуске

Версия готова к 1.0.0, когда весь основной цикл выполнен в реальном приложении,
восстановление проверено вне машины автора, нет открытых критических проблем
с сохранностью и утечками, а поставка и ограничения описаны.

Номер версии выставляется после выполнения критериев, а не вместо них.
