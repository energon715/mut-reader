# Резервная копия и восстановление

## Из приложения

1. Откройте библиотеку. «Резервные копии» → выберите папку назначения.
   В ней создаётся отдельная папка `mut-ДАТА-ID`, которая проверяется по SHA-256.
2. Храните эту папку на другом носителе. Полный recovery-код храните отдельно.
3. «Восстановить копию» → укажите именно папку с `manifest.json`, а не её родителя.
4. Выберите новую, ещё не существующую папку для библиотеки. Введите пароль,
   действовавший при создании копии, либо полный recovery-код.
5. Приложение проверит манифест, каталог, AEAD всех оригиналов и обложек и хеши
   оригиналов. Только затем опубликует восстановленную папку.
6. Откройте её как библиотеку и проверьте книги. Исходная папка и копия сохраняются.

SHA-256 без секрета подтверждает соответствие файлов манифесту; проверка
расшифрования при восстановлении подтверждает доступность зашифрованных данных.
Манифест не подписан: подмена всей папки на старую валидную копию не выявляется.

## Через vaultctl

CLI поставляется вместе с приложением и работает без графической среды и сети.
По умолчанию команды доступа запрашивают полный recovery-код. `--password`
переключает ввод на пароль. В терминале ввод скрыт; секреты не передавайте
в аргументах команд.

```sh
vaultctl backup /absolute/vault /media/backup/new-copy
vaultctl verify /media/backup/new-copy
vaultctl restore /media/backup/new-copy /absolute/restored --password
vaultctl check /absolute/restored --password
vaultctl export /absolute/restored /absolute/exported --password
```

Для восстановления по recovery-коду опустите `--password`. `check` расшифровывает
все оригиналы и обложки; `export` сохраняет оригинальные байты с правами 0600.
Существующие файлы при экспорте не перезаписываются; частичный экспорт возвращает
ошибку. Рабочие файлы экспорта незашифрованы.

Во время CLI-копирования закройте операции записи других программ. Desktop
удерживает блокировку второго desktop-процесса; прямые вызовы пакета `vault`
и сторонние программы её не соблюдают. Копирование проверяет неизменность
заголовка и HEAD в начале и конце и отклоняет изменившееся состояние.

`vaultctl purge /absolute/vault` после recovery-кода и подтверждения `PURGE`
удаляет каталог архива. Это **не гарантия безопасного стирания** на SSD,
в снимках файловой системы, резервных копиях и подкачке.

Если пароль и recovery-код потеряны, приложение не может сбросить доступ.
Если создание архива прервано до показа recovery-кода, попробуйте открыть папку
заданным паролем; не удаляйте её, если туда уже были добавлены данные.
